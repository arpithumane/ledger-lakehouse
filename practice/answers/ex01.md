Checked on 2026-11-10 with PySpark 4.0.1 locally. The landing volume holds the same files, so Databricks gives the same numbers. Open only after you've tried each task.

**1.** Every column is `string`. Without `inferSchema`, CSV columns are all strings, which is also why bronze stays as strings.
6,597 rows; 6,280 distinct `trade_id`.

**2.** Every value in this data casts cleanly.
On `'12x'`, `cast` fails the whole query with `CAST_INVALID_INPUT`: Spark 4 has ANSI mode on by default, and so does Databricks serverless.
`try_cast` returns NULL instead. Silver uses `try_cast` so one bad value can't fail the job, and then counts the NULLs it produced.

**3.** The type is `decimal(28,2)`: multiplying decimals widens the precision, and `round` sets the scale to 2. `double` can't hold most cents exactly, so totals drift.

**4.** The sum is -515,694. Without `otherwise`, an unmatched row gets NULL, and `sum` skips NULLs silently.

**5.** a: 10. b: 6. c: 1,593.
Without brackets you get `CANNOT_CONVERT_COLUMN_INTO_BOOL`. Write `(F.col("side") == "BUY") & (F.col("quantity") > 5000)`.

**6.** a: 146. b: 6,440. The total is 6,597, so 11 rows are missing.
Those 11 rows have a NULL `counterparty_id`. `NULL != 'C0001'` is NULL, not true, and `filter` keeps only true.
d: 6,451, using `~F.col("counterparty_id").eqNullSafe("C0001")` or `F.col("counterparty_id").isNull() | (F.col("counterparty_id") != "C0001")`.
In Ab Initio terms, this is the NULL handling you'd normally write explicitly in a Filter by Expression.
